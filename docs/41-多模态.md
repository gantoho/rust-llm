## 为什么要多模态？

到第 40 课为止，模型只认得文本 token。但真实世界的 LLM 早已是多模态的：

| 能力 | 问题 | 最基础的解法 |
|------|------|-------------|
| **图片理解** | "这张图里有什么？"——文本描述不了像素 | 视觉编码器（ViT）把图变成向量，塞进文本序列 |
| **图片生成** | 让模型"画"出一张图 | 先把图离散成 token，像生成文本一样生成图像 token，再解码回像素 |

本课两条通路都做**最基础但完整**的版本：能训练、能推理、能通过 API 服务出图。

## 整体架构

```
图片理解（ViT 通路）:
  PNG → 解码/resize/归一化 → patchify → ViT（双向注意力） → 投影到 n_embd
        → 原位覆写文本序列里的 P 个占位符 → 主干 Transformer 照常前向 → 文字回答

图片生成（VQ-VAE 通路）:
  训练期: PNG → patchify → 编码器 → 最近邻量化（码本） → 解码器 → 重建像素（三项损失）
  推理期: 文本 → 主干采出「图片段 token」 → 码本 id → 解码器 → unpatchify → PNG
```

两条通路共用同一套图像预处理（`patchify`）与同一个词表图片区间，但**模型是两个**：
视觉塔随主干 checkpoint 存档，VQ-VAE 是独立小模型存 `{out_dir}/vq.ckpt`。

## 一、图片理解：手写 ViT

### 1. 图像预处理与 patchify

`vision::load_image(path, size)` 做三件事：`image` crate 解码 → 双线性 resize 到 `size × size`
→ 转成 CHW 布局、像素归一化到 `[-1, 1]`。

然后 **patchify** 把图切成小块（经典 ViT 做法）：

```
64×64 图，patch_size = 16
→ (64/16)² = 16 个 patch，每个 patch 是 3×16×16 = 768 维向量
→ 输出 [P, 3·ps²]，行主序（先扫行、行内从左到右）
```

关键取舍（代码注释里写明了）：**patchify 是纯数据搬运，不是可微算子**——像素是常量输入，
不需要对输入求梯度，所以直接在 Rust 侧完成，避免为切片在 autograd 里再引入一整套索引算子。
梯度从 `Linear` 权重那侧进入。

### 2. VisionEncoder：不带 CLS 的 ViT

```
pixels [b, 3·S·S]
  │ patchify（Rust 侧）
  ▼
[b, P, 3ps²] ── Linear patch_embed ──→ [b, P, n_embd]
  │ + 可学习位置 embedding [P, d]（gather_rows 铺到 b·P 行）
  ▼
n_layer 个双向 Transformer Block（mask=None，patch 之间互相可见，复用主干 TransformerBlock）
  │ RMSNorm/LayerNorm
  ▼
Linear proj 投影到主干 n_embd → 摊平成 [b·P, n_embd]
```

与论文 ViT 的两处有意差异：

- **不引入 CLS token**：所有 patch 都要回填到文本序列的对应占位符上，加 CLS 反而没有去处
  （最基础的图片理解不需要它）。
- **风格随主干**：归一化 / FFN 风格（RMSNorm/SwiGLU）取自主干 `TransformerConfig`，
  层数/头数由 `VisionConfig` 决定——视觉塔与主干"体质"一致。

位置 embedding 初始化用小正态（N(0, 0.02)），并且**用 `gather_rows` 而不是复制成常量**——
复制成常量的话 `pos` 永远拿不到梯度，位置信息就再也不会更新。

### 3. 图像占位 token：`<|image|>` 与 ImageTokens 区间

文本里怎么表示一张图？在分词器上挂一段连续的图片 token id（排在内容词表与 BOS/EOS/PAD 之后）：

```
[内容词表][bos][eos][pad][start][ph₀..ph_{P-1}][end][vq₀..vq_{K-1}]
                                  └── P 个占位符 ──┘  └── 码本 K 个 ──┘
```

- 写 `<|image|>` 时，`Tokenizer::encode` 把它展开成 `[start, ph₀..ph_{P-1}, end]`——
  **P = (image_size / patch_size)²，与 ViT 的 patch 数一一对应**；
- `decode` 时图片段又折叠回单个 `<|image|>`（占位符逐个打印没有可读性，且往返稳定）；
- `vq₀..vq_{K-1}` 是 VQ-VAE 码本 id 的直接偏移，生成通路用，训练序列里它们就是普通 token；
- id 排在内容词表之后，**旧 checkpoint 靠"前缀行恢复 + 优化器状态补零"继续可用**（同第 39 课加 EOS 的手法）。

挂载入口是 `Tokenizer::attach_image_tokens(patch_count, codebook_size)`，幂等；
未带特殊 token 的旧分词器返回 `None`（id 空间没有 PAD 可以接续）。

### 4. forward_mm：像素在 prefill 首步注入

多模态前向的核心是**原位覆写**，序列长度完全不变：

```
文本:   [BOS] 图 : <|image|> 是 什 么 ？ [EOS]
             └─ 展开成 start + P 个占位符 + end ─┘
                ↓ prefill 首步
视觉:   ViT 输出 [b·P, n_embd] 逐行覆写 P 个占位符位置
                ↓
主干:   Transformer 照常因果前向（loss 对齐、KV cache 都不受影响）
```

`Transformer::forward_mm(idx, b, t, pixels: Option<&[f32]>, kv_cache, training)` 是唯一入口：

- `pixels = Some(...)`：第一个前向步把视觉特征写进占位符；
- `pixels = None`：与纯文本路径**逐位一致**（单测 `test_forward_mm_injects_vision_and_keeps_text_path` 保证）；
- 没配视觉塔（`model.vision = null`）的 checkpoint 像素注入会断言失败。

采样侧对应 `Generator::with_pixels(...)`：必须在**首次 `step` 之前**调用，
prompt 里没有 `<|image|>` 时（`generate --image` 入口）自动在尾部补一个；
滑动窗口回退（丢最旧行）时像素注入保持幂等（单测覆盖）。

## 二、图片生成：手写 VQ-VAE

### 1. 为什么要离散化

主干模型的输出是 softmax over 词表——它只会产生**离散 token**。所以"画图"必须先把图变成 token 序列。
**VQ-VAE**（Vector Quantized VAE）学一个码本：每个 patch 用码本里最近的一个向量代表。

```
patch 向量 z_e ──最近邻──→ 码本 id k（离散！）──查表──→ z_q ──解码器──→ 重建 patch
                              └── 这个 id 就是模型要生成的"图像 token"
```

### 2. 结构与三项损失

`Vqvae` 全部用 `Linear` 堆出来（无 conv2d，与项目"只用手写算子"一致）：

```
编码器:  [n, 3ps²] ─ Linear + ReLU ─ Linear ─→ z_e [n, D]     （patchify 复用 vision.rs）
量化:    z_e 对码本 [K, D] 求最近邻 → (id, z_q)   ← 纯 Rust，argmax 无梯度，不进 tape
解码器:  z_q ─ Linear + ReLU ─ Linear ─→ [n, 3ps²] ─ unpatchify ─→ 重建像素
```

损失是三项之和（`forward_loss`，0 维标量直接 `backward()`）：

| 损失 | 公式直觉 | 梯度去向 |
|------|---------|---------|
| **recon** | ‖重建 − 原图‖²，经 **straight-through**（`z_q = z_e + 常量差值`） | 编码器 + 解码器 |
| **codebook** | ‖码本[命中行] − z_e 快照‖² | 只进码本（把码本拉向编码器输出） |
| **commitment** | β·‖z_e − z_q 快照‖² | 只进编码器（让它别乱跑，β = 0.25） |

straight-through 的妙处：前向值用量化结果，反向 `∂z_q/∂z_e = I`——
**常量差值不进计算图**，码本收不到 recon 的梯度（由 codebook loss 负责），编码器收得到。

### 3. 码本 token 挂进词表与训练

配置了 `model.vq` 之后，训练入口（`main.rs`）按顺序做四件事：

1. **断言** `vq.image_size == vision.image_size`（像素按 vision 的尺寸加载）；
2. `{out_dir}/vq.ckpt` 已存在 → 直接 `Vqvae::load` 跳过预训练；不存在 →
   要求 `train.vq_steps > 0`（否则报错：没有码本就挂不上生成 token），
   用 `train::train_vqvae` 在 **JSONL 语料图片**（`vl.images()`）上预训练并保存；
3. `vl.attach_generation(&vq, &tokenizer)`：把每条样本的**占位符段替换为码本 token**
   （`真实 id = cb_first + 码本下标`），生成序列与理解序列混批训练；
4. 主干照常 `train`——生成任务本质上就是"续写一段图片 token"。

`vq.ckpt` 是独立二进制格式（魔数 `VQCP1` + JSON 头 + f32 数据块），
与主干的 `LLMCP2` 分开——VQ-VAE 是另一个模型，不该混进主 checkpoint。

### 4. 采样与图片段状态机

生成时模型可能吐出图片 token，采样器（`src/sample.rs`）用状态机认段：

```
期待 start ──见到 start──→ 数满 P 个码本 token ──见到 end──→ 完整图片段 ✓
   │                          │
   └─ 见到别的 token ←────────┘ 中途断了 → 丢弃（不算图）
```

只有**完整的「start + P 个码本 + end」**才算一张图（`Generator::generated_images`），
避免把半截 token 序列解码成乱码 PNG。

## 三、图文数据与训练

### VlmLoader：图文 JSONL

`train.vlm_file` 指向一个 JSONL 文件，每行一条样本：

```json
{"image": "img/0.png", "conversations": [
  {"role": "human", "content": "图:<|image|> 是什么？"},
  {"role": "gpt",   "content": "这是一只猫。"}
]}
```

- `image` 路径**相对 JSONL 所在目录**；
- 每条样本必须**恰好出现 1 次 `<|image|>`**（多了少了都报错）；
- 分词器必须已 `attach_image_tokens`（否则无法展开占位符）。

与纯文本 `DataLoader` 的差别：

| 行为 | 纯文本 DataLoader | VlmLoader |
|------|------------------|-----------|
| 切窗 | 滑动窗口切长序列 | **整条对齐，不滑窗**（一张图不能被切断） |
| 尾部 | 截断 | pad 补齐，**pad 不计 loss** |
| batch 内容 | token + 掩码 | 多带每条样本的像素 `[B, 3·S·S]` |
| 序列来源 | 单一 | 理解序列 +（配 vq 时）生成序列可切换混批 |

### 配置（本项目落地：`config/vlm.json`）

```jsonc
{
  "model": {
    "vocab_size": 0,                  // 0 = 词表大小由分词器决定（内容词 + specials + 占位符 + 码本）
    "block_size": 256,
    "vision": {                       // null = 纯文本模型，行为与加本模块之前逐位一致
      "image_size": 64, "patch_size": 8,      // → P = 64 个占位符
      "n_embd": 128, "n_head": 4, "n_layer": 2,
      "dropout": 0.1, "ph_first": 0           // ph_first 由训练入口自动写入
    },
    "vq": {                            // 可选；配了才有图片生成能力
      "image_size": 64, "patch_size": 8,      // → 64 个码本 token/图
      "latent_dim": 64, "codebook_size": 512,
      "hidden": 256, "beta": 0.25
    }
  },
  "train": {
    "train_file": "data/vlm_train.txt",  // BPE 语料（问答文本，覆盖 用户：/助手：/<|image|>）
    "tokenizer_file": null,              // null = 训练时新建分词器并存到 {out_dir}/tokenizer.json
    "out_dir": "checkpoints/vlm",        // 独立产物目录：tokenizer.json / vq.ckpt / best.ckpt / gen_image_*.png
    "vlm_file": "data/vlm/vlm.jsonl",    // null = 纯文本训练；给出则走 VlmLoader（必须配 model.vision）
    "vq_steps": 300                      // VQ-VAE 预训练步数；已有 {out_dir}/vq.ckpt 则加载跳过；0 = 强制不预训练
  }
}
```

两条**硬约束**（训练入口断言，违反直接 panic）：

- `vq.image_size` 必须等于 `vision.image_size`；
- `vq.patch_size` 必须等于 `vision.patch_size` —— 占位符数 `P = (image_size/vision.patch_size)²` 必须等于
  VQ 编码出的码本 token 数，否则 `attach_generation` 报「VQ 编码得到 x 个码，与占位符数 y 不一致」。

现成示例数据集 `data/vlm/`：360 张 64×64 合成图（6 色 × 3 形，`img/*.png`）+ `vlm.jsonl` 720 条
（每条样本恰好 1 次 `<|image|>`，一半理解问答 + 一半画图指令），BPE 语料在 `data/vlm_train.txt`。

## 四、推理与部署

### generate --image（图片理解）

```bash
# prompt 里没有 <|image|> 时自动在尾部补一个
cargo run --release -- generate --config config/config.json \
  --image data/demo.png --prompt "图里的内容是" --max-new 80

# prompt 里手写 <|image|> 指定位置
cargo run --release -- generate --config config/config.json \
  --prompt "看这张图<|image|>，用一句话描述" --image data/demo.png --max-new 80
```

- 需要 `model.vision` 配置；像素经 `Generator::with_pixels` 在 prefill 首步注入；
- **Beam Search 分支不支持图片输入**：会打日志忽略 `--image`，走纯文本 beam。

### 图片生成与出图

主干采出完整图片段后：

- **CLI**：`generate` 自动解码落盘到 `{out_dir}/gen_image_{i}.png`；
- **serve（非流式）**：VQ-VAE 解码成 PNG，以 `data:image/png;base64,...`
  内嵌进响应的 `message[0].image_url` 字段（`content` 文本里保留 `<|image|>` 字面量）；
  OpenAPI 规范里 `message` 的 schema 已同步声明该字段；
- **serve（流式）**：图片段整段采完后，在 `finish_reason` 帧**之前**单独发一帧
  只带 `delta.image_url` 的增量帧（`data: {"choices":[{"delta":{"image_url":"data:image/png;base64,..."}}]}`），
  客户端在流式对话里也能拿到图；
- 没出图或没配 VQ-VAE 时不发该帧，回包与纯文本服务逐字节一致。

## 本项目的实际实现

### 代码结构

| 文件 | 内容 |
|------|------|
| `src/vision.rs` | `VisionConfig`（默认 64/16/64/4/2）、`load_image` / `save_image` / `encode_png`、`patchify`、`VisionEncoder`（patch embed + 位置 embedding + 双向 Block + 投影） |
| `src/vqvae.rs` | `VqConfig`（默认 64/8/D=64/K=512/hidden=256/β=0.25）、`unpatchify`、最近邻 `quantize`、`Vqvae::forward_loss`（三项损失 + STE）、`encode` / `decode`、`save` / `load`（`VQCP1` 存档） |

| `src/model.rs` | `TransformerConfig::vision` / `vq`、`forward_mm` 多模态前向、`has_vision`、视觉参数随 checkpoint 存取（旧档缺视觉参数可容忍恢复） |
| `src/data.rs` | `VlmLoader::from_jsonl`（整条对齐 / pad / 像素携带）、`attach_generation`（占位符段 → 码本 token） |
| `src/train.rs` | `train_vqvae` VQ-VAE 预训练循环 |
| `src/sample.rs` | `Generator::with_pixels`、图片段状态机与 `generated_images` |
| `src/main.rs` | `vlm_file` / `vq_steps` 接线、`generate --image` 入口、`gen_image_{i}.png` 落盘 |
| `src/serve.rs` | `generated_image_uri`（data URI）、非流式 `message.image_url` 组装、`parse_chat` 读末条 `image_url`、`prepare_vision` + `b64decode`（请求图解码注入）、流式 finish 前的 `delta.image_url` 帧、OpenAPI schema |

### CLI / 训练用法（均已实测）

```bash
# 1. 图文 VLM 训练：首次会先预训练 VQ-VAE 300 步存 vq.ckpt，再训主干
cargo run --release -- train --config config/vlm.json

# 断点续训（恢复参数 / 优化器状态 / 步数；best.ckpt 每次 eval 都会更新）
cargo run --release -- train --config config/vlm.json --resume checkpoints/vlm/latest.ckpt

# 2. 图片理解（prompt 要套 SFT 模板：用户：\n输入\n助手：\n，<|image|> 写在问题前）
cargo run --release -- generate --config config/vlm.json \
  --image data/vlm/img/0.png --prompt "用户：
图:<|image|>这是什么颜色？
助手：
" --max-new 16 --temperature 0.1

# 3. 图片生成（同套模板；画图条件指令放在最前，模型采出 start 后
#    状态机自动补齐 64 个码本 token + end，落盘 {out_dir}/gen_image_{i}.png）
cargo run --release -- generate --config config/vlm.json \
  --prompt "用户：
请画一张蓝色的三角形" --max-new 100 --temperature 0.8

# 4. 服务出图 / 传图（非流式回包带 message.image_url，请求可带图）
cargo run --release -- serve --config config/vlm.json --port 8080

# 5. serve 图片理解：末条 user 消息带 image_url（data URI 或裸 base64）
$b64 = [Convert]::ToBase64String([IO.File]::ReadAllBytes("data/vlm/img/0.png"))
$json = '{"model":"vlm","messages":[{"role":"user","content":"这是什么颜色？","image_url":"data:image/png;base64,' + $b64 + '"}]}'
[IO.File]::WriteAllText("$env:TEMP\req.json", $json, [Text.UTF8Encoding]::new($false))
curl.exe -s http://127.0.0.1:8080/v1/chat/completions `
  -H "Authorization: Bearer <key>" -H "Content-Type: application/json" `
  --data-binary "@$env:TEMP\req.json"
```

- `generate --prompt` 是**裸输入**，不像训练那样自动套模板，要手写 `用户：/助手：` 行；
- 生图条件（颜色、形状）必须出现在序列**靠前的位置**——图片 start token 紧跟条件指令生成，
  模型才能把「蓝色三角形」的语义带进码本序列。

## 拓展方向

核心内容已全部实现，以下是进阶方向：

- **CLIP 式对比学习**：图文对齐训练，让视觉特征直接落在语言模型的语义空间里；
- **更高保真的生成**：VQ-VAE 换成 VQ-GAN（加对抗损失 + 感知损失）、或扩散模型（diffusion）；
- **多图 / 视频**：一条样本多个 `<|image|>`、时序帧序列（serve 目前只认末条 user 的一张图）；
- **视觉问答之外的任务**：图文混合 SFT、区域级定位（bbox token）；
- **自定义分辨率**：位置 embedding 插值支持可变 `image_size`。
