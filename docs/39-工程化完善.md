## 2. CLI 子命令设计

### 2.1 从 4 个到 7 个子命令

| 子命令 | 功能 | 状态 |
|--------|------|------|
| `train` | 训练模型 | 增强（支持 LoRA 配置、指标日志） |
| `eval` | 评估模型 | 不变 |
| `generate` | 生成文本 | 增强（支持 Beam Search） |
| **`chat`** | 交互式对话 | **新增** |
| **`finetune`** | LoRA 微调 | **新增** |
| **`preset`** | 生成预设配置 | **新增** |
| `demo` | 教学演示 | 不变 |

### 2.2 设计原则

1. **渐进式复杂度**：新手用 `demo` 验证 → `preset` 生成配置 → `train` 训练 → `generate` 生成。
   进阶用户用 `chat` 对话 → `finetune` 微调。
2. **配置优先**：超参数全在 `config.json`，命令行参数只覆盖生成/对话的采样参数。
3. **合理默认值**：所有参数都有默认值，最简情况只需 `cargo run -- train`。

## 3. 分词器序列化

### 3.1 为什么需要持久化

训练 BPE 分词器需要遍历整个语料统计频率，大语料（>100MB）可能耗时数十秒。
每次 eval / generate 都重新训练分词器是浪费。持久化后：
- 训练一次，保存到 `tokenizer.json`
- eval / generate / chat 直接加载，秒级完成
- 保证训练和推理用完全相同的词表

### 3.2 JSON 格式

```jsonc
// CharTokenizer
{
  "type": "char",
  "chars": ["H", "e", "l", "o", " ", "W", "r", "d"]
}

// BPETokenizer
{
  "type": "bpe",
  "merges": [[108, 111], ...],  // 合并规则（字节对）
  "vocab": [[72], [101], ...]   // token id → 字节序列
}
```

### 3.3 自动保存

训练时如果 `tokenizer_file` 未配置，会自动保存到 `{out_dir}/tokenizer.json`：

```jsonc
{
  "train": {
    "tokenizer_file": null  // null = 从语料训练并自动保存
  }
}
```

指定路径则直接加载，跳过训练：

```jsonc
{
  "train": {
    "tokenizer_file": "checkpoints/tokenizer.json"  // 直接加载
  }
}
```

### 3.4 推理时自动加载（无需语料）

训练完成后，推理命令（`eval` / `generate` / `chat`）**不再需要语料文件**。

代码中通过 `load_tokenizer_for_inference` 函数实现自动查找：

```rust
// src/main.rs
fn load_tokenizer_for_inference(tcfg: &config::TrainConfig, expect_vocab: usize) -> Tokenizer {
    // 1. 用户显式配置了 tokenizer_file
    if let Some(ref path) = tcfg.tokenizer_file {
        return Tokenizer::load(path);
    }
    // 2. 自动查找训练时保存的 tokenizer.json
    let auto_path = format!("{}/tokenizer.json", tcfg.out_dir);
    if std::path::Path::new(&auto_path).exists() {
        return Tokenizer::load(&auto_path);
    }
    // 3. 都没有，从语料训练（兜底）
    let train_text = load_text(&tcfg.train_file);
    build_tokenizer(tcfg, &train_text, expect_vocab)
}
```

命令行还支持 `--tokenizer` 参数直接指定路径，优先级最高：

```
1. --tokenizer 参数（命令行显式指定）
2. config.json 的 tokenizer_file 字段
3. {out_dir}/tokenizer.json（训练时自动保存的，推荐）
4. 从 train_file 语料训练（兜底，不推荐）
```

这样保证了：
- 训练和推理使用完全相同的分词器（词表一致性）
- 推理时不需要原始语料文件
- checkpoint 目录可以独立复制到其他机器使用

## 4. 预设配置

### 4.1 三个预设

| 预设 | 参数量 | 架构 | 隐藏维度 | 层数 | 上下文 | 适合场景 |
|------|--------|------|----------|------|--------|----------|
| `small` | ~2M | GPT-2 风格 | 256 | 4 | 128 | 学习/演示，CPU 几分钟 |
| `medium` | ~15M | LLaMA 风格 | 512 | 8 | 256 | 中等语料，推荐 GPU |
| `large` | ~85M | LLaMA 风格 | 768 | 12 | 512 | 较大语料，需要 GPU |

### 4.2 使用方式

```bash
# 生成配置文件
cargo run --release -- preset --name medium --output config_medium.json

# 用生成的配置训练
cargo run --release -- train --config config_medium.json
```

### 4.3 架构选择

- **small** 使用 GPT-2 风格（LayerNorm + GELU MLP + 标准 MHA），适合学习基础
- **medium / large** 使用 LLaMA 风格（RMSNorm + SwiGLU + GQA），与现代 LLM 对齐

## 5. LoRA 微调工作流

### 5.1 完整流程

```
1. 从零训练基础模型
   cargo run --release -- train --config config.json

2. 用 LoRA 在特定数据上微调
   cargo run --release -- finetune --config config_finetune.json \
       --pretrained checkpoints/best.ckpt \
       --lora-rank 16 --lora-alpha 16 --steps 1000 --lr 1e-4

3. 用微调后的模型生成
   cargo run --release -- generate --config config_finetune.json \
       --ckpt checkpoints/latest.ckpt --prompt "..."
```

### 5.2 关键参数

| 参数 | 推荐值 | 说明 |
|------|--------|------|
| `--lora-rank` | 4-64 | 越大表达力越强，参数越多 |
| `--lora-alpha` | = rank | 缩放因子，通常与 rank 相等 |
| `--lr` | 1e-4 ~ 5e-5 | 微调学习率，比从零训练小 10-100 倍 |
| `--steps` | 500-5000 | 取决于数据量，通常远少于从零训练 |

### 5.3 参数效率

以 medium 模型（~15M 参数）为例：

```
总参数：~15,000,000
LoRA 参数（rank=16，Q/K/V 各一个）：16 × 512 × 3 × 2 = 49,152
可训练比例：0.33%
```

## 6. 交互式对话模式

### 6.1 功能特点

- 持续输入文本，模型实时生成回复
- 自动维护对话历史（截断到上下文窗口内）
- 始终使用 KV Cache 加速（推理效率最高）
- 支持系统提示词（system prompt）

### 6.2 使用方式

```bash
# 基础对话
cargo run --release -- chat --config config.json

# 带系统提示
cargo run --release -- chat --config config.json --system "你是一个有帮助的助手。"

# 调整采样参数
cargo run --release -- chat --config config.json --temperature 0.7 --max-new 300
```

### 6.3 实现细节

- 使用 KV Cache 实现高效多轮推理（每轮只计算新 token）
- 对话历史自动截断到 `block_size × 4` 字符（粗略估计每个 token ~4 字符）
- 输入 `:quit` 或 `:exit` 退出

## 7. Beam Search CLI 集成

### 7.1 使用方式

```bash
# 采样生成（默认）
cargo run --release -- generate --config config.json --prompt "The fox" --max-new 100

# Beam Search 生成（确定性，质量更高）
cargo run --release -- generate --config config.json --prompt "The fox" --beam 5 --max-new 100

# 带长度惩罚
cargo run --release -- generate --config config.json --prompt "The fox" --beam 8 --length-penalty 0.8
```

### 7.2 采样 vs Beam Search

| | 采样 | Beam Search |
|---|------|-------------|
| 确定性 | 随机（不同 seed 不同结果） | 确定性（给定参数唯一结果） |
| 多样性 | 高 | 低 |
| 质量 | 中 | 高（全局最优） |
| 速度 | 快 | 慢（beam_size 倍） |
| 适合场景 | 创意写作、对话 | 翻译、摘要、事实性生成 |

## 9. 训练指标日志

### 9.1 启用方式

```jsonc
{
  "train": {
    "log_file": "training_metrics.csv"
  }
}
```

### 9.2 CSV 格式

```csv
step,lr,train_loss,val_loss,ppl,tokens_per_sec
1,0.00000600,4.142356,,,
2,0.00001200,4.121789,,,
...
250,0.00059400,2.345678,2.456789,11.67,12500
```

### 9.3 用途

- 绘制训练曲线（loss / lr / ppl 随步数变化）
- 监控训练速度（tokens_per_sec）
- 对比不同配置的训练效果
- 排查训练问题（loss 突然上升、学习率异常等）

## 10. 关键要点

- **CLI 设计**：7 个子命令覆盖训练、评估、生成、对话、微调、预设、演示的完整工作流
- **分词器持久化**：训练一次保存，后续直接加载，保证一致性
- **推理自动加载分词器**：4 级优先级查找，推理时无需语料文件
- **预设配置**：降低新手门槛，一键生成不同规模的配置文件
- **LoRA 微调**：完整工作流（加载预训练 → 注入 LoRA → 训练 → 保存），参数效率 0.1%~1%
- **交互式对话**：KV Cache 加速的多轮对话，支持系统提示
- **Beam Search CLI**：通过 `--beam` 参数直接使用，与采样生成无缝切换
- **多文件加载**：支持目录路径，自动合并 .txt 文件
- **指标日志**：CSV 格式记录训练过程，便于分析和可视化
