## 2. 为什么需要学习率调度

第 6 课我们学过梯度下降：`θ = θ - lr·g`，学习率 `lr` 决定每一步走多大。那"全程用一个固定的 lr"行不行？看看两种极端：

| 策略 | 优点 | 缺点 |
|------|------|------|
| 固定大 lr（如 0.01） | 前期下降快 | 后期在最优解附近**来回震荡**，loss 下不去，甚至发散 |
| 固定小 lr（如 0.0001） | 后期能精细收敛 | 前期爬得太慢，训练时间翻几倍 |
| **动态 lr（本课）** | 前期稳、中期快、后期细 | 多两个超参数要调（warmup 步数、总步数） |

理想的 lr 轨迹是一条"倒 U 形"：

```
lr
 │          ╭────────────────╮
 │         ╱                  ╲
 │        ╱                    ╲
 │  ╱────╱                      ╲
 │ ╱                             ╲
 └──────────────────────────────────▶ step
   0     warmup 结束           训练结束
         （lr 达到 max）       （lr 降到 min）
```

- **初期**：lr 从很小开始（warmup），保护刚起步、还很脆弱的参数；
- **中期**：lr 维持在最大值附近，快速下降；
- **后期**：lr 逐渐变小（cosine decay），在损失曲面的"沟底"精细收敛，不会跳过最优解。

这就是本课 `LRScheduler` 做的事情：**先 warmup 线性爬升，再 cosine 曲线衰减**。

## 3. Warmup：先热个身

### 3.1 公式

warmup 阶段（`step < warmup_steps`），学习率从 0 线性升到最大值：

```
lr(step) = max_lr × (step + 1) / warmup_steps
```

注意分子里的 **`step + 1`**：`step` 从 0 开始数，`step + 1` 保证第 0 步的 lr 是 `max_lr / warmup_steps`（而不是 0），
到第 `warmup_steps - 1` 步时 lr 正好是 `max_lr × warmup_steps / warmup_steps = max_lr`。

### 3.2 为什么训练初期要用小学习率

| 原因 | 解释 |
|------|------|
| 初始参数是随机的 | `Linear::new` 用均匀分布初始化，此时梯度方向"噪声很大"，大步子容易把参数推飞 |
| AdamW 的二阶动量还没"热" | 第 17 课：AdamW 的 `v` 从 0 开始，前几步偏差修正后 `√v̂` 很小，有效步长会被放大——**初期 Adam 反而更激进**，需要小 lr 压住 |
| 大模型训练的标配 | GPT-3、LLaMA 等真实大模型训练都用 warmup，是公认的稳定性技巧 |

> 直觉：刚上冰面的新手滑冰，先小步慢走找平衡（warmup），站稳了再加速（大 lr）。

## 4. Cosine decay：按余弦曲线收尾

### 4.1 公式

warmup 结束后，学习率按**半个余弦周期**从 `max_lr` 衰减到 `min_lr`：

```
progress = (step - warmup_steps) / (total_steps - warmup_steps)     // 0 → 1
cosine   = 0.5 × (1 + cos(π × progress))                            // 1 → 0
lr(step) = min_lr + (max_lr - min_lr) × cosine
```

### 4.2 关键点

| progress | cos(π·progress) | cosine 系数 | lr 取值 |
|----------|-----------------|-------------|---------|
| 0（刚出 warmup） | cos 0 = 1 | 1 | `max_lr` |
| 0.25 | cos(π/4) ≈ 0.707 | 0.854 | `min + 0.854·(max-min)` |
| 0.5（半程） | cos(π/2) = 0 | 0.5 | `(max_lr + min_lr) / 2` |
| 0.75 | cos(3π/4) ≈ -0.707 | 0.146 | `min + 0.146·(max-min)` |
| 1（训练结束） | cos π = -1 | 0 | `min_lr` |

余弦曲线在两端（progress ≈ 0 和 ≈ 1）**斜率平缓**、在中间（progress ≈ 0.5）**斜率最陡**，翻译成 lr 就是：

- 刚离开 warmup 时 lr 在 max 附近"多停留一会儿"（给足中期快速下降的时间）；
- 训练后期 lr 平缓地逼近 `min_lr`（在沟底精细搜索，不震荡）。

> 为什么末期要小 lr？损失曲面在高维空间里像"沟壑"，大 lr 会在沟底来回弹跳；小 lr 才能贴着沟底慢慢走到最低点。
> 而且末期 loss 下降本来就慢，用小 lr 不会拖慢多少，却能让最终 loss 更漂亮。

我们的代码里 `min_lr` 取的是 `max_lr × 0.1`（见 5.3 节），即最终学习率衰减到最大值的十分之一。

## 5. `LRScheduler` 实现讲解

### 5.1 结构体

`src/train.rs` 第 20 课小节：

```rust
/// 学习率调度器：warmup + cosine decay
pub struct LRScheduler {
    warmup_steps: usize,
    total_steps: usize,
    max_lr: f32,
    min_lr: f32,
    step: usize,
}

impl LRScheduler {
    pub fn new(warmup_steps: usize, total_steps: usize, max_lr: f32, min_lr: f32) -> Self {
        LRScheduler {
            warmup_steps,
            total_steps,
            max_lr,
            min_lr,
            step: 0,
        }
    }
    // ...
}
```

| 字段 | 含义 |
|------|------|
| `warmup_steps` | warmup 持续多少步（前 N 步线性爬升） |
| `total_steps` | 训练总步数（cosine 衰减的终点） |
| `max_lr` | 学习率峰值 |
| `min_lr` | 学习率下限（衰减终点） |
| `step` | **当前已走到的步数计数**（内部状态，从 0 开始） |

### 5.2 `lr()`：按阶段算当前学习率

```rust
pub fn lr(&self) -> f32 {
    if self.step < self.warmup_steps {
        // 线性 warmup
        self.max_lr * (self.step as f32 + 1.0) / self.warmup_steps.max(1) as f32
    } else {
        // cosine 衰减：从 max_lr 平滑降到 min_lr
        let progress = (self.step - self.warmup_steps) as f32
            / (self.total_steps - self.warmup_steps).max(1) as f32;
        let progress = progress.min(1.0);
        let cosine = 0.5 * (1.0 + (std::f32::consts::PI * progress).cos());
        self.min_lr + (self.max_lr - self.min_lr) * cosine
    }
}
```

公式 ↔ 代码对照表：

| 公式 | Rust 代码 | 说明 |
|------|----------|------|
| `lr = max_lr·(step+1)/warmup_steps` | `self.max_lr * (self.step as f32 + 1.0) / self.warmup_steps.max(1) as f32` | warmup 分支。`.max(1)` 防止 `warmup_steps = 0` 时除零 |
| `progress = (step-warmup)/(total-warmup)` | `(self.step - self.warmup_steps) as f32 / (self.total_steps - self.warmup_steps).max(1) as f32` | cosine 分支的进度，范围 `[0,1]` |
| `progress = min(progress, 1)` | `let progress = progress.min(1.0);` | 万一总步数被改小、`step` 超过 `total_steps`，progress 封顶 1，lr 停在 `min_lr` 不再下降 |
| `cosine = 0.5(1+cos(π·progress))` | `0.5 * (1.0 + (std::f32::consts::PI * progress).cos())` | 半个余弦周期，从 1 平滑到 0 |
| `lr = min_lr + (max_lr-min_lr)·cosine` | `self.min_lr + (self.max_lr - self.min_lr) * cosine` | 在 `[min_lr, max_lr]` 之间插值 |

> 注意分支边界：当 `step == warmup_steps` 时走 cosine 分支，此时 `progress = 0`、`cosine = 1`，lr 恰好等于 `max_lr`——
> warmup 的终点和 cosine 的起点**无缝衔接**，lr 曲线没有断点。

### 5.3 `step()` 与在训练循环里的用法

```rust
pub fn step(&mut self) {
    self.step += 1;
}
```

`step()` 每训练一步调用一次，把内部计数 +1，从而推动 `lr()` 前进。在 `train_gpt` 里和 AdamW 配合：

```rust
// src/train.rs train_gpt
let mut opt = AdamW::new(cfg.max_lr, params.clone(), cfg.weight_decay);
let mut scheduler = LRScheduler::new(cfg.warmup_steps, cfg.steps, cfg.max_lr, cfg.min_lr);
// ...
for step in start_step..cfg.steps {
    // ... 前向、反向、梯度裁剪 ...
    let cur_lr = scheduler.lr(); // 先取当前步的学习率（scheduler.step() 之后会变成下一步的）
    opt.lr = cur_lr;             // 把"当前步的学习率"写进优化器（AdamW.lr 是 pub 字段）
    opt.step();                  // 优化器用这个 lr 更新参数
    opt.zero_grad();
    scheduler.step();            // 步数 +1，为下一步准备新的 lr
    // ...
}
```

| 代码 | 作用 |
|------|------|
| `AdamW::new(cfg.max_lr, params.clone(), cfg.weight_decay)` | 优化器初始 lr 就是 `max_lr`，权重衰减来自 `TrainConfig` |
| `LRScheduler::new(cfg.warmup_steps, cfg.steps, cfg.max_lr, cfg.min_lr)` | `min_lr` 来自 `TrainConfig`（demo 里取 `max_lr × 0.1 = 3e-4`） |
| `let cur_lr = scheduler.lr(); opt.lr = cur_lr;` | 每步**先取当前步的 lr** 再塞给优化器——`AdamW.lr` 是 `pub` 字段，可以直接赋值 |
| `scheduler.step()` | 计数器前进，下一轮循环 `lr()` 就是新的学习率 |

**配合逻辑一句话**：调度器负责"算 lr"，优化器负责"用 lr 更新参数"，两者通过 `opt.lr = scheduler.lr()` 对接。

## 6. 训练日志解读：`lr 0.002947 → 0.000300`

### 6.1 我们的训练配置

`src/main.rs` 的 `demo_gpt` 用 `TrainConfig` 传参（演示 3）：

```rust
let tcfg = config::TrainConfig {
    seed: 42,
    batch_size: 8,
    steps: 600,
    max_lr: 3e-3,
    warmup_steps: 50,
    eval_every: 100,
    ..config::TrainConfig::default()
};
train::train_gpt(&model, &tokenizer, &loader, &tcfg, None, None, &mut rng);
```

| 参数 | 值 | 含义 |
|------|-----|------|
| `steps` | 600 | 训练总步数 |
| `batch_size` | 8 | 每步 8 个样本 |
| `max_lr` | `3e-3` = 0.003 | 学习率峰值 |
| `warmup_steps` | 50 | 前 50 步线性爬升 |
| `eval_every` | 100 | 每 100 步打印一次日志 |
| `min_lr`（默认） | `3e-4` | `TrainConfig::default()` 提供，恰好 = max_lr × 0.1 |

于是 `train_gpt` 内部：`min_lr = max_lr × 0.1 = 0.0003`，调度器为 `LRScheduler::new(50, 600, 0.003, 0.0003)`。

### 6.2 日志打印的时机（避免看错）

`train_gpt` 里 `cur_lr` 在 **`scheduler.step()` 之前**取值并用于更新：

```rust
let cur_lr = scheduler.lr();   // 取"本步"的学习率（scheduler 还没 +1）
opt.lr = cur_lr;
opt.step();
opt.zero_grad();
scheduler.step();              // 之后才 +1（为下一步准备计数）
let last = step + 1 == cfg.steps;
if (step + 1) % cfg.eval_every == 0 || last {
    println!(
        "step {:>5} | lr {:.6} | train_loss {:.4}",
        step + 1,              // 日志从 1 开始数（显示 100、200、…）
        cur_lr,                // 打印的是"本步"的 lr
        loss.item()
    );
}
```

注意两个细节：一是日志里的 `step` 是 `step + 1`（循环变量从 0 开始，打印时 +1，显示 100、200、…）；
二是 `scheduler.step()` 虽然在打印之前执行，但打印的 `cur_lr` 是本步开头就取好的——所以**日志里的 `lr` 就是"本步实际用于参数更新的学习率"**，不存在错位（旧的实现把打印放在 `scheduler.step()` 之后、显示的是下一步的 lr，本轮修复后已对齐）。

### 6.3 三个关键值怎么来的

**① 第一个打印点 `0.002947`（step 100）**

demo 配置 `eval_every = 100`，所以第 100 次迭代（循环变量 step=99，scheduler 计数=99）才第一次打印：

```
progress = (99 - 50) / (600 - 50) = 49/550 ≈ 0.089
cosine   = 0.5 × (1 + cos(π × 0.089)) ≈ 0.9805
lr = min_lr + (max_lr - min_lr) × cosine = 0.0003 + 0.0027 × 0.9805 ≈ 0.002947   ✓
```

**② warmup 段为什么看不到**

`eval_every = 100 > warmup_steps = 50`，warmup 段（step 0-49）没有任何打印点，所以日志里**看不到** 0.00006 起步的线性爬升。把 `eval_every` 改成 10 就能看到：step 10/20/30/40 的 lr 依次是 `0.0006 → 0.0012 → 0.0018 → 0.0024`（每步增加 `max_lr / warmup_steps = 0.003 / 50 = 0.00006`，10 步就是 0.0006），然后平滑进入 cosine 段。

**③ 最后 `0.000300`（step 600）**

最后一步（循环变量 step=599，计数=599）progress 封顶到 1，`cosine = 0.5 × (1 + cos π) = 0`：

```
lr = min_lr + (max_lr - min_lr) × 0 = min_lr = 0.0003   ✓
```

### 6.4 真实日志序列（`cargo run --release -- demo` 原样输出）

| 日志 step | scheduler 计数 | 阶段 | lr（打印值） | 计算过程 |
|-----------|---------------|------|--------------|----------|
| 100 | 99 | cosine | **0.002947** | progress = 49/550 ≈ 0.089，lr ≈ 0.00295 |
| 200 | 199 | cosine | 0.002540 | progress = 149/550 ≈ 0.271，lr ≈ 0.00254 |
| 300 | 299 | cosine | 0.001850 | progress = 249/550 ≈ 0.453，lr ≈ 0.00185 |
| 400 | 399 | cosine | 0.001096 | progress = 349/550 ≈ 0.635，lr ≈ 0.00110 |
| 500 | 499 | cosine | 0.000518 | progress = 449/550 ≈ 0.816，lr ≈ 0.00052 |
| 600 | 599 | cosine 末 | **0.000300** | progress ≈ 0.998（接近 1），落到 `min_lr` |

这条曲线正是第 4.2 节那张表：**先平、中陡、末缓**。对比 loss 日志：前期 loss 快速下降（lr 大），
后期 loss 缓慢逼近平台（lr 小、精细收敛）——这就是"调度"在训练曲线上留下的痕迹。

> 小技巧：把 `eval_every` 改成 10，就能看到 warmup 段每 10 步 +0.0006 的线性爬升，
> 以及 cosine 段更密的 lr 变化——对照 6.3 的公式验证每一步。

## 7. 动手练习

1. **改 warmup 步数**：把 `config.json` 里的 `warmup_steps` 从 50 改成 0 和 200，分别训练，观察 loss 曲线差异——warmup 太短初期是否震荡？太长是否拖慢中期？
2. **改 min_lr**：把 `min_lr` 改成 `3e-5` 和 `1.5e-3`，对比最终 loss。想想 min_lr 设太高会有什么后果（后期"精细收敛"没了）。
3. **绘制 lr 曲线**：写个小程序，以 step 为横轴画出训练过程的 lr 曲线，确认它是"先线性爬升、再余弦衰减"的倒 U 形。
4. **对比固定 lr**：把 `train_gpt` 改成固定 `opt.lr = cfg.max_lr`（不调 `scheduler`），对比 loss——体会调度带来的"同样的步数，更好的收敛"。
5. **看懂日志**：把 `eval_every` 改小（如 10），重新 `cargo run`，观察 warmup 段的 lr 爬升——每步增加 `max_lr / warmup_steps`，确认和公式一致。

## 8. 本课总结

- **为什么需要调度**：固定大 lr 后期震荡、固定小 lr 前期太慢，动态 lr 兼顾"稳、快、细"。
- **warmup**：前 `warmup_steps` 步 `lr = max_lr × (step+1)/warmup_steps` 线性爬升，保护训练初期的随机参数和 AdamW 未热身的动量。
- **cosine decay**：`lr = min_lr + (max_lr - min_lr) × 0.5 × (1 + cos(π·progress))`，从 `max_lr` 平滑衰减到 `min_lr`。
- **`LRScheduler`**：`lr()` 按 `step` 计数选分支算 lr，`step()` 推进一步；在 `train_gpt` 里通过 `opt.lr = scheduler.lr()` 喂给 AdamW。
- **日志解读**：日志中 `lr 0.002947 → … → 0.000300` 就是 warmup → cosine decay 的完整轨迹。
