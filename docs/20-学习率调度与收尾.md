## 2. 为什么需要学习率调度

第 6 课我们学过梯度下降：`θ = θ - lr·g`，学习率 `lr` 决定每一步走多大。那"全程用一个固定的 lr"行不行？看看两种极端：

| 策略 | 优点 | 缺点 |
|------|------|------|
| 固定大 lr（如 0.01） | 前期下降快 | 后期在最优解附近**来回震荡**，loss 下不去，甚至发散 |
| 固定小 lr（如 0.0001） | 后期能精细收敛 | 前期爬得太慢，训练时间翻几倍 |
| **动态 lr（本课）** | 前期稳、中期快、后期细 | 多两个超参数要调（warmup 步数、总步数） |

理想的 lr 轨迹是一条"倒 U 形"：

```
lr
 │          ╭────────────────╮
 │         ╱                  ╲
 │        ╱                    ╲
 │  ╱────╱                      ╲
 │ ╱                             ╲
 └──────────────────────────────────▶ step
   0     warmup 结束           训练结束
         （lr 达到 max）       （lr 降到 min）
```

- **初期**：lr 从很小开始（warmup），保护刚起步、还很脆弱的参数；
- **中期**：lr 维持在最大值附近，快速下降；
- **后期**：lr 逐渐变小（cosine decay），在损失曲面的"沟底"精细收敛，不会跳过最优解。

这就是本课 `LRScheduler` 做的事情：**先 warmup 线性爬升，再 cosine 曲线衰减**。

## 3. Warmup：先热个身

### 3.1 公式

warmup 阶段（`step < warmup_steps`），学习率从 0 线性升到最大值：

```
lr(step) = max_lr × (step + 1) / warmup_steps
```

注意分子里的 **`step + 1`**：`step` 从 0 开始数，`step + 1` 保证第 0 步的 lr 是 `max_lr / warmup_steps`（而不是 0），
到第 `warmup_steps - 1` 步时 lr 正好是 `max_lr × warmup_steps / warmup_steps = max_lr`。

### 3.2 为什么训练初期要用小学习率

| 原因 | 解释 |
|------|------|
| 初始参数是随机的 | `Linear::new` 用均匀分布初始化，此时梯度方向"噪声很大"，大步子容易把参数推飞 |
| AdamW 的二阶动量还没"热" | 第 17 课：AdamW 的 `v` 从 0 开始，前几步偏差修正后 `√v̂` 很小，有效步长会被放大——**初期 Adam 反而更激进**，需要小 lr 压住 |
| 大模型训练的标配 | GPT-3、LLaMA 等真实大模型训练都用 warmup，是公认的稳定性技巧 |

> 直觉：刚上冰面的新手滑冰，先小步慢走找平衡（warmup），站稳了再加速（大 lr）。

## 4. Cosine decay：按余弦曲线收尾

### 4.1 公式

warmup 结束后，学习率按**半个余弦周期**从 `max_lr` 衰减到 `min_lr`：

```
progress = (step - warmup_steps) / (total_steps - warmup_steps)     // 0 → 1
cosine   = 0.5 × (1 + cos(π × progress))                            // 1 → 0
lr(step) = min_lr + (max_lr - min_lr) × cosine
```

### 4.2 关键点

| progress | cos(π·progress) | cosine 系数 | lr 取值 |
|----------|-----------------|-------------|---------|
| 0（刚出 warmup） | cos 0 = 1 | 1 | `max_lr` |
| 0.25 | cos(π/4) ≈ 0.707 | 0.854 | `min + 0.854·(max-min)` |
| 0.5（半程） | cos(π/2) = 0 | 0.5 | `(max_lr + min_lr) / 2` |
| 0.75 | cos(3π/4) ≈ -0.707 | 0.146 | `min + 0.146·(max-min)` |
| 1（训练结束） | cos π = -1 | 0 | `min_lr` |

余弦曲线在两端（progress ≈ 0 和 ≈ 1）**斜率平缓**、在中间（progress ≈ 0.5）**斜率最陡**，翻译成 lr 就是：

- 刚离开 warmup 时 lr 在 max 附近"多停留一会儿"（给足中期快速下降的时间）；
- 训练后期 lr 平缓地逼近 `min_lr`（在沟底精细搜索，不震荡）。

> 为什么末期要小 lr？损失曲面在高维空间里像"沟壑"，大 lr 会在沟底来回弹跳；小 lr 才能贴着沟底慢慢走到最低点。
> 而且末期 loss 下降本来就慢，用小 lr 不会拖慢多少，却能让最终 loss 更漂亮。

我们的代码里 `min_lr` 取的是 `max_lr × 0.1`（见 5.3 节），即最终学习率衰减到最大值的十分之一。

## 5. `LRScheduler` 实现讲解

### 5.1 结构体

`src/train.rs` 第 20 课小节：

```rust
/// 学习率调度器：warmup + cosine decay
pub struct LRScheduler {
    warmup_steps: usize,
    total_steps: usize,
    max_lr: f32,
    min_lr: f32,
    step: usize,
}

impl LRScheduler {
    pub fn new(warmup_steps: usize, total_steps: usize, max_lr: f32, min_lr: f32) -> Self {
        LRScheduler {
            warmup_steps,
            total_steps,
            max_lr,
            min_lr,
            step: 0,
        }
    }
    // ...
}
```

| 字段 | 含义 |
|------|------|
| `warmup_steps` | warmup 持续多少步（前 N 步线性爬升） |
| `total_steps` | 训练总步数（cosine 衰减的终点） |
| `max_lr` | 学习率峰值 |
| `min_lr` | 学习率下限（衰减终点） |
| `step` | **当前已走到的步数计数**（内部状态，从 0 开始） |

### 5.2 `lr()`：按阶段算当前学习率

```rust
pub fn lr(&self) -> f32 {
    if self.step < self.warmup_steps {
        // 线性 warmup
        self.max_lr * (self.step as f32 + 1.0) / self.warmup_steps.max(1) as f32
    } else {
        // cosine 衰减：从 max_lr 平滑降到 min_lr
        let progress = (self.step - self.warmup_steps) as f32
            / (self.total_steps - self.warmup_steps).max(1) as f32;
        let progress = progress.min(1.0);
        let cosine = 0.5 * (1.0 + (std::f32::consts::PI * progress).cos());
        self.min_lr + (self.max_lr - self.min_lr) * cosine
    }
}
```

公式 ↔ 代码对照表：

| 公式 | Rust 代码 | 说明 |
|------|----------|------|
| `lr = max_lr·(step+1)/warmup_steps` | `self.max_lr * (self.step as f32 + 1.0) / self.warmup_steps.max(1) as f32` | warmup 分支。`.max(1)` 防止 `warmup_steps = 0` 时除零 |
| `progress = (step-warmup)/(total-warmup)` | `(self.step - self.warmup_steps) as f32 / (self.total_steps - self.warmup_steps).max(1) as f32` | cosine 分支的进度，范围 `[0,1]` |
| `progress = min(progress, 1)` | `let progress = progress.min(1.0);` | 万一总步数被改小、`step` 超过 `total_steps`，progress 封顶 1，lr 停在 `min_lr` 不再下降 |
| `cosine = 0.5(1+cos(π·progress))` | `0.5 * (1.0 + (std::f32::consts::PI * progress).cos())` | 半个余弦周期，从 1 平滑到 0 |
| `lr = min_lr + (max_lr-min_lr)·cosine` | `self.min_lr + (self.max_lr - self.min_lr) * cosine` | 在 `[min_lr, max_lr]` 之间插值 |

> 注意分支边界：当 `step == warmup_steps` 时走 cosine 分支，此时 `progress = 0`、`cosine = 1`，lr 恰好等于 `max_lr`——
> warmup 的终点和 cosine 的起点**无缝衔接**，lr 曲线没有断点。

### 5.3 `step()` 与在训练循环里的用法

```rust
pub fn step(&mut self) {
    self.step += 1;
}
```

`step()` 每训练一步调用一次，把内部计数 +1，从而推动 `lr()` 前进。在 `train_gpt` 里和 AdamW 配合：

```rust
// src/train.rs train_gpt
let mut opt = AdamW::new(max_lr, params.clone(), 0.01);
let mut scheduler = LRScheduler::new(warmup_steps, steps, max_lr, max_lr * 0.1);
// ...
for step in 0..steps {
    // ... 前向、反向、梯度裁剪 ...
    opt.lr = scheduler.lr();   // 把"当前步的学习率"写进优化器（AdamW.lr 是 pub 字段）
    opt.step();                // 优化器用这个 lr 更新参数
    opt.zero_grad();
    scheduler.step();          // 步数 +1，为下一步准备新的 lr
    // ...
}
```

| 代码 | 作用 |
|------|------|
| `AdamW::new(max_lr, params.clone(), 0.01)` | 优化器初始 lr 就是 `max_lr`，`weight_decay = 0.01` |
| `LRScheduler::new(warmup_steps, steps, max_lr, max_lr * 0.1)` | **`min_lr` 直接取 `max_lr × 0.1`**，不用额外传 |
| `opt.lr = scheduler.lr()` | 每步把调度器算好的 lr 塞给优化器——`AdamW.lr` 是 `pub` 字段，可以直接赋值 |
| `scheduler.step()` | 计数器前进，下一轮循环 `lr()` 就是新的学习率 |

**配合逻辑一句话**：调度器负责"算 lr"，优化器负责"用 lr 更新参数"，两者通过 `opt.lr = scheduler.lr()` 对接。

## 6. 训练日志解读：`lr 0.00012 → 0.003 → 0.00030`

### 6.1 我们的训练配置

`src/main.rs` 的 `demo_gpt` 调用（注意参数顺序）：

```rust
train::train_gpt(&model, &tokenizer, &loader, 600, 8, 3e-3, 50, 100, &mut rng);
//                                          steps  batch  max_lr  warmup  eval_every
```

| 参数 | 值 | 含义 |
|------|-----|------|
| `steps` | 600 | 训练总步数 |
| `batch_size` | 8 | 每步 8 个样本 |
| `max_lr` | `3e-3` = 0.003 | 学习率峰值 |
| `warmup_steps` | 50 | 前 50 步线性爬升 |
| `eval_every` | 100 | 每 100 步打印一次日志 |

于是 `train_gpt` 内部：`min_lr = max_lr × 0.1 = 0.0003`，调度器为 `LRScheduler::new(50, 600, 0.003, 0.0003)`。

### 6.2 日志打印的时机（容易看错）

`train_gpt` 里打印在 **`scheduler.step()` 之后**：

```rust
opt.zero_grad();
scheduler.step();                       // 先计数 +1
if step % eval_every == 0 || step == steps - 1 {
    println!("step {:>5} | lr {:.5} | loss {:.4}", step, scheduler.lr(), loss.data()[0]);
}
```

所以**日志里打印的 `lr` 是"下一步将使用的学习率"**（计数 = 当前迭代号 + 1），
而本步实际用于参数更新的 lr 是 `opt.lr = scheduler.lr()` 取到的那一份（计数 = 当前迭代号）。

### 6.3 三个关键值怎么来的

**① 第一次打印 `0.00012`（step 0）**

第 0 次迭代结束时 `scheduler.step()` 把计数推到 1，于是打印：

```
lr = max_lr × (step + 1) / warmup_steps = 0.003 × (1 + 1) / 50 = 0.00012   ✓
```

（本步真正用来更新参数的 lr 是 0.003 × 1 / 50 = 0.00006。）

**② warmup 峰值 ≈ `0.003`**

warmup 终点（计数 = 50）时：

```
lr = 0.003 × (50 + 1) / 50 = 0.00306 ≈ 0.003
```

紧接着 cosine 分支起点（progress = 0）的 lr 恰好等于 `max_lr = 0.003`，两者无缝衔接。
（日志里看不到 0.00306 这个值——打印间隔 100 步，而 warmup 只有 50 步，warmup 段只有 step 0 一个打印点。）

**③ 最终 `0.00030`（step 599）**

最后一步 progress 封顶到 1，`cosine = 0.5 × (1 + cos π) = 0`：

```
lr = min_lr + (max_lr - min_lr) × 0 = min_lr = 0.0003   ✓
```

### 6.4 完整日志序列（估算）

打印点是 `step = 0, 100, 200, 300, 400, 500, 599`（`%100==0` 或最后一轮），对应日志 lr（按 6.3 的公式推算）：

| 日志 step | 调度器计数 | 阶段 | lr（约） | 说明 |
|-----------|-----------|------|----------|------|
| 0 | 1 | warmup | **0.00012** | 起步：`0.003×2/50` |
| 100 | 101 | cosine | 0.00294 | 刚从峰值下来一点 |
| 200 | 201 | cosine | 0.00253 | 平稳下滑 |
| 300 | 301 | cosine | 0.00183 | 过半程，接近 (max+min)/2 = 0.00165 |
| 400 | 401 | cosine | 0.00108 | 明显变小 |
| 500 | 501 | cosine | 0.00051 | 逼近下限 |
| 599 | 600 | cosine 末 | **0.00030** | 落到 `min_lr` |

这条曲线正是第 4.2 节那张表：**先平、中陡、末缓**。对比 loss 日志：前期 loss 快速下降（lr 大），
后期 loss 缓慢逼近平台（lr 小、精细收敛）——这就是"调度"在训练曲线上留下的痕迹。

> 小技巧：`cargo run` 后盯着日志的 `lr` 列看，前 50 步它在线性爬升（但只打印了一次），
> 之后按余弦曲线一路衰减到 0.0003。改 `eval_every`（比如改成 10）就能看到 warmup 段更密的 lr 变化。

## 8. 后续展望：从这里出发

20 课只是"入门级 GPT"的终点，却是真实 LLM 世界的起点。按性价比排序，值得继续的方向：

### 8.1 数据和规模

| 方向 | 现状 | 下一步 |
|------|------|--------|
| 语料 | `CORPUS` 只是一小段英文故事（约 700 字符） | 换成更大语料（如 WikiText、OpenWebText 子集），模型才能学到真实语言结构 |
| 模型规模 | `GPTConfig::tiny`：64 维、2 层 | 增大 `n_embd`/`n_layer`/`block_size`（先换 GPU） |
| 训练步数 | 600 步 × batch 8 | 上万步 + 更大 batch，loss 才能逼近语料的理论下限 |

### 8.2 直接能做的代码级改进

- **RoPE 接入**（最顺手的下一步）：第 19 课 `rotary` 已实现，把它接进 `MultiHeadAttention`（先修反向符号），替换掉正弦 `pos_emb`；
- **RMSNorm**：把 LayerNorm 的均值项去掉，更快且效果相当（LLaMA 在用）；
- **GQA / MQA**：多头共享 KV，配合 KV cache 大幅省显存；
- **更好的分词器**：加大 BPE 合并次数 / 词表，或换 SentencePiece 风格。

### 8.3 架构前沿（了解即可）

- **MoE（混合专家）**：把每个 Block 的 MLP 换成多个"专家" + 一个路由器，每个 token 只激活少数专家。
  参数量大幅增加但计算量可控（Mixtral、DeepSeek 系列就是代表）；
- **长度外推**：RoPE 训练长度外会失效，用 NTK-aware scaling、YaRN 等方法把上下文"撑"长；
- **稀疏注意力 / Flash Attention**：优化注意力本身的计算与 IO，长上下文必备。

### 8.4 真正的并行（从单机 CPU 到多卡 GPU）

我们现在是**单线程 CPU、零依赖**的教学实现，真实训练要靠并行：

| 并行方式 | 切分维度 | 一句话 |
|----------|----------|--------|
| 数据并行 | batch | 每张卡算一份 batch 的梯度，然后 all-reduce 求和，大家参数保持一致 |
| 张量并行 | 矩阵 | 把单个 `Linear` 的权重按列/按行切到多张卡，一起算一次前向 |
| 流水线并行 | 层 | 把 12 层切成几段，卡 1 算 1-4 层、卡 2 算 5-8 层…… |

想实战的话，可以先把本项目移植到 `candle` / `burn` 等 Rust 深度学习框架上（它们封装了 GPU 和 autograd），
或者用 `rayon` 给张量运算加上多线程——那是"工程优化"的另一个故事了。

> 学习这条路没有终点：**从手写张量到训练小 GPT，你走完了框架背后的 90% 黑盒；剩下的 10% 是工程与规模。**

## 9. 动手练习

1. **改 warmup 步数**：把 `main.rs` 里的 `warmup_steps` 从 50 改成 0（注意 `lr()` 里 `.max(1)` 会兜底，不会除零）和 200，分别训练，观察 loss 曲线差异——warmup 太短初期是否震荡？太长是否拖慢中期？
2. **改 min_lr 比例**：把 `train_gpt` 里的 `max_lr * 0.1` 改成 `max_lr * 0.01` 和 `max_lr * 0.5`，对比最终 loss。想想 min_lr 设太高会有什么后果（后期"精细收敛"没了）。
3. **绘制 lr 曲线**：写个 10 行小程序（或用 6.4 的公式在表格/脚本里算一遍），以 step 为横轴画出 600 步的 lr 曲线，确认它是"先线性爬升、再余弦衰减"的倒 U 形。
4. **对比固定 lr**：把 `train_gpt` 改成固定 `opt.lr = max_lr`（不调 `scheduler`），训练 600 步对比 loss——体会调度带来的"同样的步数，更好的收敛"。
5. **看懂日志**：把 `eval_every` 从 100 改成 10，重新 `cargo run`，观察 warmup 段的 lr 爬升——它每步增加 `max_lr/warmup_steps = 0.003/50 = 0.00006`，所以每 10 步增加 0.0006（0.00012 → 0.00072 → 0.00132 → …），确认和公式一致。

## 10. 本课总结（也是全项目的结语）

- **为什么需要调度**：固定大 lr 后期震荡、固定小 lr 前期太慢，动态 lr 兼顾"稳、快、细"。
- **warmup**：前 `warmup_steps` 步 `lr = max_lr × (step+1)/warmup_steps` 线性爬升，保护训练初期的随机参数和 AdamW 未热身的动量。
- **cosine decay**：`lr = min_lr + (max_lr - min_lr) × 0.5 × (1 + cos(π·progress))`，从 `max_lr` 平滑衰减到 `min_lr`（本项目取 `max_lr × 0.1`）。
- **`LRScheduler`**：`lr()` 按 `step` 计数选分支算 lr，`step()` 推进一步；在 `train_gpt` 里通过 `opt.lr = scheduler.lr()` 喂给 AdamW。
- **日志解读**：`0.00012`（第 0 步打印，`0.003×2/50`）→ warmup 峰值 ≈ `0.003` → 终点 `0.00030`（`min_lr`），打印发生在 `scheduler.step()` 之后，所以显示的是"下一步的 lr"。
- **20 课全回顾**：地基（张量/自动微分）→ 神经网络 → 分词器 → Transformer → 训练推理 → 现代技巧（AdamW/KV cache/RoPE/调度），`cargo run` 达成全部验收标准。
- **展望**：更大语料与模型、RoPE 接入、MoE、真正的并行（数据/张量/流水线）、RMSNorm/GQA/外推技巧——每一步都能在这个项目上继续长出来。

> 最后一句：**一个能跑的、完全由你手写的小 GPT，就是打开大模型世界最好的钥匙。**
> 20 课结束，学习才刚刚开始。祝玩得开心！
