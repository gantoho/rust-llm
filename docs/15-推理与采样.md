## 1. 本课要搞懂的问题

1. 模型输出的 logits 是分数，怎么变成真正的文本？
2. 为什么"每次都选概率最大的 token"（argmax）效果很差？
3. temperature、top-k、top-p 分别解决了什么问题？它们在代码里怎么实现？
4. 模型为什么会卡在"太太太太太太……"出不来？重复惩罚（repetition penalty）是怎么打断它的？
5. `generate` 生成一句文本时，每步发生了什么？KV cache 模式和全量模式有什么不同？

## 2. 生成的基本流程

训练完成后（第 13-14 课），模型已经学会了"给前缀，预测下一个 token"。生成文本就是把这件事**反复做**：

```
"Once upon a"
   │ 前向：model.forward(ctx, 1, T, ...)
   ▼
logits（每个 token 一个分数，未归一化）
   │ 采样：sample_token(logits, opts, recent, rng)   // opts = T/top-k/top-p/重复惩罚
   ▼
下一个 token id
   │ 拼回上下文
   ▼
"Once upon a time" → 再前向 → 再采样 → …… 直到 max_new 个 token
```

关键在于中间那一步：**logits 是分数，不是文本**。怎么从分数里选 token，决定了生成质量。

## 3. 为什么不能直接 argmax

最朴素的想法：把 logits 做 softmax 变成概率，然后**永远选概率最大的**（这就是贪心解码 / argmax）。它的毛病很典型：

| 现象 | 原因 |
|------|------|
| 重复、呆板 | 一旦某个 token 概率最高，之后每一步都会倾向选它，陷入 "the the the the..." 的死循环 |
| 毫无惊喜 | 概率第二、第三的候选被完全无视，模型"不敢"走任何低概率但合理的路 |
| 容易跑偏 | 一步选错（概率 0.4 的次优解可能是对的），后续全部跟着错，且无法回头 |

大模型的真实需求是"**在合理的候选里随机一点**"：既不能完全确定（呆板），也不能完全乱来（胡言乱语）。于是有了下面四个旋钮。

## 4. temperature：调节分布的"锐度"

softmax 的公式，引入温度 T 后：

```
pᵢ = exp(zᵢ / T) / Σⱼ exp(zⱼ / T)
```

| T 的取值 | 效果 | 直觉 |
|----------|------|------|
| T < 1（如 0.8） | 分数差距被放大，分布更"尖" | 更确定、更保守、更连贯 |
| T = 1 | 标准 softmax | 默认 |
| T > 1（如 1.5） | 分数差距被压缩，分布更"平" | 更随机、更有创造力、更易出错 |

代码（[src/sample.rs](../src/sample.rs) `sample_token` 第 2 步，排在重复惩罚之后）：

```rust
let inv_temp = 1.0 / opts.temperature.max(1e-5);   // 1e-5 是温度下限，防止 0 除
for l in penalized.iter_mut() {
    *l *= inv_temp;
}
```

数值例子：logits = `[1.0, 2.0, 0.5, 0.1]`（词表 4 个 token）：

| 温度 | scaled | softmax 概率 | token 1 概率 |
|------|--------|--------------|--------------|
| T = 0.5 | [2.0, 4.0, 1.0, 0.2] | [0.11, **0.83**, 0.04, 0.02] | 0.83（更"确定"） |
| T = 1.0 | [1.0, 2.0, 0.5, 0.1] | [0.21, **0.57**, 0.13, 0.09] | 0.57 |
| T = 2.0 | [0.5, 1.0, 0.25, 0.05] | [0.25, **0.41**, 0.19, 0.16] | 0.41（更"随机"） |

## 5. top-k：只在前 k 个里选

思想：分数排最后的那些 token 本来就是"凑数"的，干脆把它们从候选里删掉，只在前 k 个里分配概率。

代码（`sample_token` 第 3-4 步：先按分数从高到低排序，再截断）：

```rust
let mut items: Vec<(usize, f32)> = penalized.iter().enumerate().map(|(i, &v)| (i, v)).collect();
items.sort_by(|a, b| b.1.partial_cmp(&a.1).unwrap_or(std::cmp::Ordering::Equal));

if opts.top_k > 0 && items.len() > opts.top_k {
    items.truncate(opts.top_k);   // top_k = 0 表示不启用
}
```

## 6. top-p（nucleus）：按累积概率截断

思想：不看"固定个数"，而是**从高到低累加概率，直到累积概率达到 p**，把后面的全部丢掉。候选集合大小随分布自动变化——分布集中时集合小，分布分散时集合大。

代码（`sample_token` 第 5-6 步：先 softmax 得到概率，再按累积概率截断）：

```rust
// 5. softmax 得到概率（减最大值防溢出）
let max = items.iter().map(|(_, v)| *v).fold(f32::NEG_INFINITY, f32::max);
let mut probs: Vec<f32> = items.iter().map(|(_, v)| (*v - max).exp()).collect();
let sum: f32 = probs.iter().sum();
for p in probs.iter_mut() { *p /= sum; }

// 6. top-p：从高到低累加概率，直到超过 p，后面的全部丢弃
if opts.top_p < 1.0 {
    let mut cum = 0.0;
    let mut keep = items.len();
    for (i, p) in probs.iter().enumerate() {
        cum += p;
        if cum >= opts.top_p { keep = i + 1; break; }
    }
    items.truncate(keep);   // 丢掉尾部
    probs.truncate(keep);
    let s: f32 = probs.iter().sum();
    for p in probs.iter_mut() { *p /= s; }   // 重新归一化
}
```

沿用上面的例子（T=1.0，概率 [0.21, 0.57, 0.13, 0.09]，已按分数排序）：

```
top_p = 0.9：
  0.57  → 累计 0.57（< 0.9 继续）
  0.21  → 累计 0.78（< 0.9 继续）
  0.13  → 累计 0.91（≥ 0.9 停）→ 保留前 3 个，丢弃第 4 个
```

> 相比 top-k 的"一刀切固定个数"，top-p 更聪明：概率分布尖的时候只留 1-2 个候选，平的时候留一堆。实践中 top-k 和 top-p 经常**一起开**（本项目 main.rs 里就是 `top_k=10, top_p=0.9` 同时启用）。

## 7. 重复惩罚：打断自我强化的重复循环

temperature / top-k / top-p 都只做一件事：**截断分布再抽样**。它们对"分布长什么样"没有发言权，所以治不了下面这种病：

```
我们？"与他的了。”么？""寶玉道：“的呢人的說的說了他笑笑道:"你說我。“么。么，
寶玉我．我要吃著著玉了了， 這老太太太太太太太太太太太太太太太太太太太太太太太太
太太太太太太太太太太太太太太太太太太太太太太太太太太太太太太太太太太太太太太太……
```

（这是一个真实小模型的输出，训练了 4000 步、验证 ppl 619。）

**为什么会卡住**：一旦上下文里出现"太"，注意力就让"太"成为"下一个 token 最可能是太"的证据，于是"太"的概率被推到很高；采样又选了"太"，上下文里就有两个"太"，证据更强……这是个**正反馈**。top-k=40 也没用——循环里的"太"永远在 top-1，截断只是把跳出去的那 39 个候选划掉。

**怎么治**：给"最近出现过的 token"记账，把它们本轮的 logit 压低，这就是 **repetition penalty**：

```rust
// 正值除以系数、负值乘以系数 —— 两种情况下数值都变小，因此更难被抽中
for &id in recent {
    if let Some(l) = penalized.get_mut(id) {
        *l = if *l > 0.0 {
            *l / opts.repetition_penalty
        } else {
            *l * opts.repetition_penalty
        };
    }
}
```

两个细节值得留意：

1. **正负要分开处理**。logit 是实数，可能是负的。直接乘 `1/系数` 会把负 logit 变得更接近 0（= 概率变大），正好反向；所以正值除、负值乘，方向才都是"压低"。
2. **作用位置在 temperature 之前**。惩罚先改原始 logit，再统一做 temperature 缩放——这与 HuggingFace 的处理器顺序一致（`RepetitionPenaltyLogitsProcessor` 属于 logits processor，跑在 warper 之前）。

回看窗口 `repetition_window` 是另一个旋钮：只看最近 N 个 token（本项目默认 64）。窗口太小的毛病是"刚说过的还罚不罚"管不住；太大则会把"的""了"这类高频虚词也一起压掉，句子反而散架——所以窗口和系数都不是越大越好，`1.05~1.3` + `64~128` 是常见区间。

**实测对照**（同一 prompt、"我们"，同一种子，只改 `--repetition-penalty`）：

| 参数 | 输出 |
|------|------|
| `1.0`（关闭） | `我们？"与他的了。”么？""寶玉道：“的呢人的說的說了他笑笑道:"你說我。“么。么， 他才也什么不寶玉我．我要吃著著玉了了， 這老太太太太太太太太太太太太……` |
| `1.1`（默认） | `我们？"寶玉笑道：么了。么好了我也說了這那話說，又不干著他來了．二爺呢，我就睡著說，我沒好的，我還叫什么要了他是寶玉來呢， 這的的和我你們去了。` |

惩罚不负责让内容变对（那是模型规模和训练量的事），它只负责**别让模型卡死在一个字上**。区别在于：前者是坏掉了，后者是"很笨但没有坏"。

## 8. 汇总：sample_token 的完整七步

[src/sample.rs](../src/sample.rs) 的 `sample_token` 把上面所有招数串起来：

| 步骤 | 做什么 | 对应代码 |
|------|--------|----------|
| 1 | 重复惩罚：压低最近出现过的 token | `*l / opts.repetition_penalty`（或 `*l * ...`） |
| 2 | 除以 temperature 缩放 | `*l *= 1.0 / opts.temperature.max(1e-5)` |
| 3 | 按分数从高到低排序 | `items.sort_by(...)` |
| 4 | top-k 截断（k>0 时） | `items.truncate(opts.top_k)` |
| 5 | softmax 转概率（减最大值防溢出） | `(*v - max).exp()` 再归一化 |
| 6 | top-p 按累积概率截断并重新归一化 | `cum >= opts.top_p` 时 `truncate` |
| 7 | 按概率随机采样 | `rng.next_f32()` 做轮盘赌 |

第 7 步的"轮盘赌"采样：

```rust
let mut u = rng.next_f32();          // 均匀随机数 [0, 1)
for (i, p) in probs.iter().enumerate() {
    if u < *p { return items[i].0; } // 落进第 i 段的概率 = pᵢ
    u -= p;                          // 没落进就减去这段，继续往后看
}
items.last().map(|(i, _)| *i).unwrap_or(0)
```

数学上：选到 token i 的概率正好等于 pᵢ。这保证了——概率高的 token 被选中的机会大，但概率低的也有机会被选中，这就是"随机性"的来源。

## 9. generate：一步一步生成整句文本

全量模式（无 KV cache）的流程，[src/sample.rs](../src/sample.rs)：

```rust
let block_size = model.cfg.block_size;
let mut ids = tokenizer.encode(prompt);        // 起始文本 → id 序列
if ids.is_empty() {
    ids.push(0);   // 空 prompt：先喂一个 token，避免 0 长度上下文导致下标下溢
}
// 仅在使用 KV cache 时才分配缓存，全量模式不浪费内存
let mut cache = use_kv_cache.then(|| model.new_kv_cache());

for _ in 0..max_new {
    if cache.as_ref().is_some_and(|c| c[0].seq_len() >= block_size) { break; }  // KV 模式的长度上限

    let start = ids.len().saturating_sub(block_size);   // 只保留最近 block_size 个
    let ctx = &ids[start..];

    // 推理不需要反向：no_grad 下不挂计算图、不分配梯度缓冲
    let logits = crate::tensor::no_grad(|| {
        if use_kv_cache {
            let c = cache.as_mut().unwrap();
            if c[0].seq_len() == 0 {
                model.forward(ctx, 1, ctx.len(), Some(c), false)      // 首次：喂整个 prompt
            } else {
                model.forward(&ids[ids.len() - 1..], 1, 1, Some(c), false)  // 之后：只算最新 1 个
            }
        } else {
            model.forward(ctx, 1, ctx.len(), None, false)   // 全量：每次重算整个上下文
        }
    });

    let v = model.cfg.vocab_size;
    let n = logits.numel();
    let last_row = &logits.data()[n - v..];      // 取最后一个位置的 logits
    // 重复惩罚的回看窗口在这里截好再交给 sample_token（窗口 0 = 不惩罚）
    let recent = if opts.repetition_window == 0 {
        &[][..]
    } else {
        &ids[ids.len().saturating_sub(opts.repetition_window)..]
    };
    let next = sample_token(last_row, opts, recent, rng);
    ids.push(next);                              // 拼回上下文，进入下一轮
}

tokenizer.decode(&ids)                           // id 序列 → 文本
```

> 采样参数打包在 `SampleOpts { temperature, top_k, top_p, repetition_penalty, repetition_window }` 里，
> 而不是一长串函数入参——`generate` 的参数本来就多，再加两个标量会到 11 个。

> `model.forward` 的最后一个参数是 `training`：推理时传 `false`，不做 dropout。

逐步拆解：

1. **编码**：`tokenizer.encode(prompt)` 把起始文本变成 id 序列。
2. **截断上下文**：`ctx = ids[ids.len() - block_size ..]`，上下文超过 `block_size` 时只保留最近的一段——模型"记不住"更早的历史。
3. **前向拿 logits**：全量模式下每次都把整个 `ctx` 重新算一遍（慢，但无需额外内存）。
4. **取最后一个位置**：前向输出形状是 `[B*T, vocab_size]`，这里 B=1，最后一个位置即 `data[n-v..]`，它对应"基于当前全部上下文预测的下一个 token"。
5. **采样并拼接**：`sample_token` 选出一个 id，`ids.push(next)`，进入下一轮。
6. **解码**：循环结束后 `tokenizer.decode(&ids)` 把整条序列还原成文本（包含 prompt 和生成的部分）。

## 10. KV cache 模式的上下文限制：block_size 截断

KV cache（第 25 课详解）的思路：生成第 N 个 token 时，前 N-1 个 token 的 K/V 不需要重算，缓存起来每步只算最新的 1 个 token，大幅加速推理。但它带来一个限制，代码注释里写得很明白：

```rust
// KV cache 模式：上下文总长达到 block_size 就停（缓存无法像全量模式那样截断历史）
if use_kv_cache && cache[0].seq_len() >= block_size {
    break;
}
```

两种模式对"超长上下文"的处理对比：

| 模式 | 上下文超过 block_size 时 | 代价 |
|------|--------------------------|------|
| 全量（`use_kv_cache = false`） | 每次把 `ctx` 截断到最近 block_size 个 token，可以无限生成 | 每步都要重算整个上下文，慢 |
| KV cache（`use_kv_cache = true`） | 缓存里已经累积了全部历史 K/V，**无法丢弃**，只能停止生成 | 生成的 token 总数被限制在 `block_size` 以内 |

> 所以 KV cache 在 `max_new` 还没用完时可能提前 `break`——这是"加速"换来的"长度上限"。而且它会**静默地**让输出变短，所以 `generate` 在窗口写满时会向 stderr 打印一行 `[warn]`，别忽略它。
>
> main.rs 的 demo 里，生成 1（`false`）和生成 2（`true`）用**同一个 prompt + 同一个种子**，生成 2 恰好是生成 1 的前缀，这才是"cache 只改计算方式、不改生成分布"的验证。注意不能像早先那样给两次生成传不同 prompt（"Once upon a" vs "The fox"），那样输出不同只是采样不同，什么都证明不了。

## 11. 参数怎么配：一个经验表

| 场景 | temperature | top-k | top-p | repetition-penalty |
|------|-------------|-------|-------|--------------------|
| 要求准确、连贯（代码、摘要） | 0.2 ~ 0.7 | 小（5~20） | 0.8 ~ 0.9 | 1.0 ~ 1.05 |
| 通用对话 | 0.7 ~ 0.9 | 30~50 | 0.9 ~ 0.95 | 1.1（默认） |
| 创意写作、头脑风暴 | 0.9 ~ 1.2 | 大或关闭 | 0.95 ~ 1.0 | 1.05 ~ 1.15 |
| 小模型长文本（容易卡循环） | 0.8 ~ 1.0 | 40~100 | 0.9 ~ 0.95 | 1.15 ~ 1.3 |

main.rs 里的演示配置：`temperature=0.8, top_k=10, top_p=0.9, repetition_penalty=1.1`，是一个偏保守、够通顺的组合。

> 一个直观规律：**temperature 越高越需要重复惩罚**。高温让分布更平、更容易抽到尾部 token，也更容易一头扎进重复循环；反过来，低温 + 小 top-k 本身就很少重复，惩罚加过头反而会让本该重复的字（如"太太"）被强行拆开。

## 12. 动手练习

1. 把 `generate` 的 `temperature` 分别改成 0.1 和 2.0 跑一遍，观察输出从"复读机"到"胡言乱语"的变化。
2. 把 `top_k` 改成 1（等价于只在概率最高 token 附近贪心）再跑，观察重复现象。
3. 把 `top_p` 改成 1.0（关闭）但保留 `top_k=10`，对比输出差异。
4. 在 `sample_token` 的轮盘赌循环里打印每次的 `u` 和命中的 token，手动验证"命中概率 ≈ pᵢ"。
5. 用足够长的 prompt（超过 `block_size`，如 40 个字符）分别跑 `use_kv_cache = false` 和 `true`，观察 KV 模式提前停止生成的现象。
6. 固定 `--seed`，把 `--repetition-penalty` 从 1.0 逐步调到 2.0，观察输出从"卡死重复"→"正常但笨"→"句子散架"的整条曲线，体会系数并非越大越好。

## 13. 本课总结

- 生成 = 前向拿 logits → 采样选 token → 拼回上下文 → 循环
- **argmax 不可取**：必然重复、呆板、无法回头
- 四个旋钮：**重复惩罚**压低刚出现过的 token、**temperature** 调分布锐度、**top-k** 按个数截断、**top-p** 按累积概率截断，最后按概率随机采样
- `sample_token` 七步：重复惩罚 → 缩放 → 排序 → top-k → softmax → top-p → 轮盘赌
- 重复惩罚是唯一能治"自我强化重复循环"的旋钮：top-k/top-p 只截断分布，管不了分布本身长什么样
- `generate` 全量模式每次重算上下文；KV cache 模式加速但受 `block_size` 长度限制，超限即停
- 下一步（第 16 课）：把所有零件拼起来，训练一个小 GPT 并生成有意义的长文本
